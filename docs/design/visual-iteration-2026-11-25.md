# 视觉与交互迭代 2026-11-25：从「深色应用」到「暗房」

> 范围：移动端（iOS/iPadOS）与 macOS 共用同一套 Flutter 渲染层，一次改动两端同时生效。
> 定性：**不是重做**。信息架构、数据流、播放内核、Agent 能力全部不动；动的是「观众第一眼看到什么、手往哪放、什么时候被打断」。
> 结论先出：这一次改了三件看得见的事（调色板、顶栏与首页的噪声、片库的状态日志），并把真正值钱的东西——**交互层**——写成可验收的规格，分成 M1/M2 两步。

---

## 1. 参考拆解（都看过原图，不是凭印象）

取图来源：Firecore 官网、Mac App Store 截屏、iina.io、Plex App Store 截屏。原始文件留在 `/tmp/ref/`。

### Infuse（iOS/iPadOS）

- **底是纯黑**，内容区几乎没有"面板"色：卡片直接落在黑上，用封面自己撑起颜色。
- **大标题左对齐**（"Home" 约 40–44 pt，w600），标题下面不留说明句。
- 顶部只有**一个浮起的胶囊**（筛选 + 刷新），其余靠滚动。
- 首屏 = 一张 16:9 横封 + 圆形的播放按钮压在封面中央；下面是"标题 / 年份"两行小字。
- 再往下是**彩色快捷块**（橙 / 蓝 / 粉的实心圆角块 + 白色线性图标），一行三个，标题在块下方。
- 分区标题右侧是**橙色 "See All"**——整个界面唯一的彩色文字。
- 详情页：**满幅剧照出血到屏幕四边**，顶部只有两个圆形玻璃按钮（返回、更多）；标题压在剧照上；元信息一行小灰字用 `·` 分隔 + 一个分级小胶囊；主 CTA 是一枚**宽药丸**（浅灰底 + 深字，写着 "Resume 00:01:39"）；下面一排五个圆形次操作；再往下才是简介与评分源（TMDB 7.6 / 烂番茄 77 / 观众 73%）。

### IINA（macOS）

- 视频 = 100% 的画面。没有一个常驻的工具栏。
- 控制条是**浮在画面上的一条圆角药丸**（约 14 px 圆角、半透明黑），两行：上行「音量滑杆 · 上一集/播放/下一集 · 五个工具图标」，下行「当前时间 · 粗进度线 + 白色圆点 · 总时长」。
- 标题栏只有文件名，右侧两个图标；红绿灯照旧。
- 学到的：**macOS 上"少"不是省略，是把东西收进一个可召唤的浮层**。

### Plex（iOS）

- 用**倾斜的海报墙 + 品牌蓝辉光**制造"片库很大"的情绪，正文仍是黑底大字。
- 学到的：颜色可以服务于"规模感"，但只在一个区域出现，不铺满全屏。

### Apple TV（系统）

- 焦点驱动：选中即放大 + 视差 + 轻微高光；文字极少，靠画面说话。

### 四家的共性（可直接当规则用）

1. 黑是主角：`#000`–`#0D0D0E`，不是"深蓝灰"。
2. 封面是主角：任何一屏，画面占比 ≥ 50%。
3. chrome 极少：一屏最多一个浮起的控件组。
4. **只有一个强调色**，且只出现在"要你按的地方"。
5. 字号跨度大（标题 : 正文 ≈ 2.4–2.8 倍），中间档很少。
6. 圆角统一（8/12/16 三档以内），阴影几乎为零。
7. 动效只做 150–250 ms 的位移与透明度。

## 2. 我们现在的实测问题（取色来自 2026-11-25 的首页截图）

用脚本解 PNG 逐像素取样（`docs/screens/trim-2026-11-25-home.png`，390×844）：

| 位置 | 实测 RGB | 与"黑"的偏差 | 读起来是什么 |
| --- | --- | --- | --- |
| 顶部背景 | `rgb(25, 35, 50)` | B−R = **+25** | 冷蓝雾 |
| 底部导航 | `rgb(24, 32, 44)` | B−R = **+20** | 冷蓝玻璃 |
| 主卡片 | `rgb(16, 21, 26)` | B−R = **+10** | 蓝灰面板 |
| 中部背景 | `rgb(12, 15, 16)` | +4 | 接近黑（正确的那一层） |
| 主按钮填充 | `rgb(164, 164, 166)` | 0 | 一块中性灰，**没有"唯一该按"的信号** |

一眼可见的四条结构问题：

1. **蓝色雾**：`ambient: #60738C` 在玻璃与辉光里被反复叠，整屏偏冷，和"影片"没有关系。黑不够黑，画面就永远像"未加载完"。
2. **五个顶栏图标等权并排**（搜索 / 片源 / 设置 / 帮助 / 待看），没有一个比另一个重要；375 px 宽度下它们挤掉了标题的呼吸。
3. **首屏有教学句**：「摇一摇刷新 · 下拉解耦」。手势是好的，说明书不该占首屏。
4. **三个并列 chip 没有主次**（生成片单 / 轻松电影 / 体检片库）；片库首句是「N 部电影 · N 部剧集 · …个来源，统一管理」——这是日志，不是标题；卡片标题在卡内，元信息又在卡外重复一遍。

## 3. 风格契约（本版硬规则，写下来才不会漂）

**风格名：暗房（Darkroom）**——影院刚关灯的那三秒：纯黑、暖纸白、一线琥珀。

- 参考三张，各取一样：Infuse 取「黑底 + 大标题 + 宽药丸 CTA」；IINA 取「浮起的控制条 + 时间轴在上」；Plex 取「颜色只服务情绪，不铺满」。
- **三条硬规则**
  1. 底色只用三层：`#070708 / #0D0D0E / #151516`。**任何蓝色只能来自画面本身**，不许来自 UI。
  2. 只有一个强调色 `#E8C7A2`（暖砂），只出现在「要你按的地方」和「小映出现的地方」。
  3. 字号只取六档：`34 / 22 / 17 / 15 / 12 / 11`；标题行高 1.02，正文 1.5。
- **禁做清单**：彩色渐变当装饰；图标代替标题；超过两档圆角；玻璃叠玻璃；动效超过 300 ms；把"状态句"当副标题。
- 为什么是它：这是一个**私人影院**。观众要的是"灯关了，画面亮起来"，不是"又一个控制台"。

## 4. 交互创新：三个别人没有的层

皮肤只能让人多看一眼，**交互才决定他下次还开不开**。下面是按"我们已经有的数据"推出来的，不是许愿：

### 4.1 胶片轨（Film Rail）——把进度条变成第二条内容轨道

现状：所有播放器的进度条都只表示"时间"。Infuse、Apple TV、Plex、IINA 都一样。

我们有的：精彩帧（带时间码）、AI 字幕/译配的断点、章节、以及用户自己标过的帧。

做法：
- 进度条下方长出**细刻度**：精彩帧是琥珀小竖线、章节是灰色长线、译配断点是虚线。
- 拖动时，游标上方浮出**该时刻的帧缩略图**（复用精彩帧的采样），松手落位。
- 双指长按进入**微距 scrub**：1 像素 = 0.1 s，用来找"那一帧"。
- 验收判据：拖到任一精彩帧刻度，缩略图与落位误差 < 0.3 s；刻度数量 = 该片精彩帧数量。

### 4.2 小映在场，而不是"打开一个面板"

现状：Agent 是一个输入框（首页那块玻璃卡）。它要求用户**先想清楚要问什么**，这是工具的心智，不是陪伴的心智。

做法：
- 播放时，小映是画面右下角一个**呼吸光点**（2 s 周期，透明度 0.35↔0.6），不占 1 px 画面。
- 只有在你**暂停**、或它**有话要说**（"这一段的配乐是…"）时，才浮出一行字 + 一个"展开"。
- 展开是浮窗（已有），收起只收窗口（已实现），影片不暂停（已实现）。
- 验收判据：连续播放 10 分钟，光点不引起一次误触；暂停后 400 ms 内出现，不遮挡字幕区。

### 4.3 AI 作为"音轨"，而不是按钮

现状：解说/译配是设置里的开关或独立按钮，用户要"想到它"才能用。

做法：
- 播放器的音轨选择器里直接出现 **「小映·解说」「小映·译配」**，和"普通话 / 原声 / 5.1"并列。选了就生效，像换一条音轨一样自然。
- 画质增强做成**按住对比**：按住画面 = 原始，松手 = 增强（修图软件的习惯），不给你"设置项"。
- 验收判据：切换音轨后 1 s 内出声；按住画面 300 ms 内可见对比，松手复位；全程不弹任何对话框。

### 4.4 跨端接力（Mac ↔ 手机）

- Mac 的时间轴上显示"这台机器 + 手机"的两个进度点；点手机那个点，把手机推到同一秒。
- 已有基础：遥控/局域网配对（1.8.0 起）、播放进度同步。

### 5.1 实测前后（同一张 390×844，脚本逐像素取样）

| 位置 | 改前 RGB（B−R） | 改后 RGB（B−R） |
| --- | --- | --- |
| 顶部背景 | `25,35,50`（**+25**） | `7,7,8`（**+1**） |
| 底部导航 | `24,32,44`（+20） | `27,27,28`（**+1**） |
| 主卡片 | `16,21,26`（+10） | `14,15,16`（+2） |
| 中部背景 | `12,15,16`（+4） | `12,15,16`（+4） |

结论：**蓝色偏移从 +25 降到 +1**，冷雾消失；黑回到中性黑，剩下的颜色只来自封面与环境光。

### 5.3 这一版还不够好的地方（自己先说）

- **没有封面时首屏仍然偏空**：测试片库里的条目没有 posterUrl/backdropUrl，整块 hero 只剩文字。真实片库有封面时是正常的（见 Infuse 同位置的做法），但"没有元数据"的条目需要更强的氛围兜底，下一版会做。
- **顶栏还是五个图标**：这次只降了噪（配色与提示句），没有动结构。收成「搜索 + 溢出」是 M2 的事——它要动 `app_shell.dart`，与播放器改动分开做。
- **播放器一行没动**：本轮零改动。`player_screen.dart` 2400 行，视觉与交互要一起改才有意义，放进 M2。

验证：`flutter analyze` → 449 issues / **0 error / 0 warning**（基线 467）；`flutter test --concurrency=1` → 全过（数字见下）；macOS Release 与 iOS 模拟器两端均实际构建并运行。

## 6. 下一版（M2）要做的，和为什么现在不做

- **Film Rail**：要接 `frame_bookmarks` 与字幕断点的时间码，改播放器控制层——2400 行的 `player_screen.dart`，一次改完风险高于收益；先按 §4.1 的判据补测试，再动 UI。
- **小映光点**：需要播放器的 overlay 生命周期（暂停/恢复/字幕区避让），与上面同一处代码。
- **音轨化 AI**：依赖 `watch_ai` 的译配输出格式，要先确认它能否按"轨"切段。
- **按住对比**：需要两路渲染或两套滤镜切换，属于内核改动，不在视觉迭代里混做。

## 7. 明确不做

- 跟随系统取色 / 动态取色：会破坏"只有一个强调色"。
- 海报墙 3D 倾斜：Plex 的招，但会牺牲扫视效率。
- 重做玻璃材质：现有 `liquid_glass.dart` 已经够用，这一版只降噪不换料。
- 给每个平台各写一套视觉：Flutter 单渲染层是本项目的核心成本优势，不拆。
