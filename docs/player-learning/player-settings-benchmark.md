# 播放器设置对标：Infuse 与 ddPlayer 类客户端

> 目的：把两份真实设置页截图拆成**可执行的产品判断**——哪些思路值得学、哪些要改成我们自己的做法、哪些不做。
> 素材：Infuse（深色，设置全集 12 张）+ 一款国产播放器（浅色，Infuse 式片库 + 弹幕 + AI 字幕，6 张）。
> 对照基线：Flutter 1.17.0 现状 + Rust 线 M3 计划（`docs/plan/rust-rewrite-plan.md`）。
> 结论口径：**学思路、不照抄配置项**。判断标准只有三条——用户是否真的会改它、改错代价大不大、我们有没有能力用更少的设置做到同样效果。

## 0. 一句话结论

两家竞品都把「播放手感」拆成了**十几个可以单独拧的旋钮**，但真正被用户记住的只有四件事：**跳得准（片头片尾/步长）、续得上（进度/下一集）、看得懂（字幕/音轨语言）、压得住（倍速/长按加速）**。SeeWow 现在缺的不是旋钮数量，而是这四件事的**默认值与记忆**：默认值合理，用户就不进设置页。

## 1. 竞品设置拆解

### 1.1 Infuse：把播放器做成「可调的放映机」

| 分组 | 设置项 | 背后的思路 |
| --- | --- | --- |
| 播放 | 快进/后退 10 秒（可改）、跳过模式=时间、跳过片头/片尾=开启 | 把「跳过」做成**可预测的时间动作**，不依赖片源打点；片头片尾用记忆库兜底 |
| 播放 | 连续播放、继续播放、后台播放 | 「接着看」是默认行为，不是开关特权 |
| 播放 | 缓存方式=自动、实时预览、正在播放 API | 把**等待**藏起来（预取 + 拖动缩略图），把**外部联动**暴露出来（系统媒体控制） |
| 播放 | 播放速度=正常、AI 画质增强=自动、Dolby Vision、转码=原画质 | 画质链路按「源能力 → 屏能力」自动决策，用户只在越界时被通知 |
| 音频 | HDMI/AirPlay 5.1、声音增强=禁用、降混声道=原始、Dolby Atmos | 默认**不加工**音频（禁用增强、原始降混），把加工留给明确选择 |
| 系列与版本 | 电影/剧集显示系列、TMDB 系列、自定义系列、多版本合并、合并后默认版本=自动 | 同一部片的多份拷贝是**一个条目**，播放时按设备能力挑版本 |
| 元数据 | 自动下载、内嵌海报优先、本地优先、Logo、外部评分、缓存大小 + 清空 | 优先级可解释（本地 > 内嵌 > 在线），缓存**可见可清** |
| 家长控制 | 限制、Face ID、锁定应用/搜索、评级上限、每次交互需 PIN | 儿童场景靠**分级 + 锁**，不靠藏内容 |
| PRO | 4K/更多格式、无损 24bit、AirPlay/Cast、云同步、云端串流、永久更新 | 付费点是**格式与云端**，不是基础播放 |

### 1.2 ddPlayer 类：把「看剧的琐事」自动化

| 分组 | 设置项 | 背后的思路 |
| --- | --- | --- |
| 播放 | 自动续播（上次位置**前 3 秒**）、预加载下一集、短视频模式（上滑下一集）、默认倍速、快进时长、按钮快进、长按加速 2x | 「上一集结束到下一集开始」中间不该有操作；3 秒回退是为了**接上语境** |
| 语言 | 默认音轨语言=不自动选择、默认字幕语言=简体中文、AI 字幕翻译跟随系统 | 语言偏好是**一次设定、永久生效**，不是每集重选 |
| AI 字幕 | 本机识别 + 翻译模型下载/删除、逐语言管理 | 模型是**可管理的资产**（能看占用、能删），不是黑盒 |
| 弹幕 | 显示按钮、弹幕源、3 个 API 地址 | 把弹幕当**可插拔源**，官方不绑死一家 |
| 片库 | 媒体库分类、关联文件夹、海报缓存占用、资料缓存占用、清空缓存 | 缓存**分项计量**，用户知道删掉会失去什么 |
| 隐私 | App 锁定、数字密码 | 手机被借走时，片库本身是隐私 |
| 记录 | 近 7 天播放数、按视频/图片/音乐分类、文件名搜索 | 「我上周看了什么」是**独立入口**，不是设置里的统计 |
| 免费/ PRO | 倍速、刮削、定时关闭、片头片尾、AI 字幕、语言偏好、收藏、图片预取 | 把「省事的自动化」当付费点——说明这些功能**用户感知强** |

## 2. SeeWow 现状（1.17.0 基线）

| 能力 | 现状 | 结论 |
| --- | --- | --- |
| 手势（双击左右、上下调音量/亮度、长按） | 有（`playback_gestures.dart`） | 保留，补「步长可配 + 长按倍率可配」 |
| 断点续播 | 有进度写入，无「前 3 秒回退」策略 | **增强**（见 3.1） |
| 字幕切换 | 有 `subtitle_dialog`（内外挂、多轨） | 保留；缺「默认字幕语言」记忆 |
| 音轨选择 | 有 | 缺「默认音轨语言」记忆 |
| 倍速 | 有基础倍速 | 缺「默认倍速 / 长按加速倍率」两项偏好 |
| 片头片尾跳过 | 无 | **采纳思路**（时间式 + 每剧记忆） |
| 定时关闭 | 无 | **采纳**（睡前场景，成本极低） |
| 预加载下一集 | 无 | **采纳**（连播体验的分水岭） |
| AI 字幕（本机识别） | 无（有 AI 陪看/配音/翻译） | **评估后做**：与现有模型管理合并，不新增一套 |
| 弹幕 | 无 | **不做主线**，以「外部弹幕源」形态留给 M4 之后 |
| 多版本合并 / 系列聚合 | 元数据有 `externalIds`，条目未合并 | **增强**（片库整洁度直接影响观感） |
| 播放统计「记录」页 | 无独立页 | **采纳**（近 7 天 + 继续观看） |
| App 锁 / 家长控制 | 有敏感画面检测，无锁 | **采纳轻量版**（四位密码锁片库） |
| 画质自动决策（HDR/DV/转码） | Flutter 靠系统播放器；Rust 线 M5 专门做 | 已在计划内，不重复 |
| 音频默认不加工 | 有音效/降混设置 | 对齐 Infuse：默认 `原始`，加工显式开 |
| 缓存分项计量 | 有下载管理，无「海报/元数据缓存」分项 | **采纳**（设置页给数字 + 清空） |

## 3. 决定：学什么、怎么增强、不做什么

### 3.1 立刻学（进 Rust M3，成本低、感知强）

1. **续播回退 3 秒**：`ResumePolicy` 已有 30 秒门槛与看完判定；再加 `rewind_ms = 3000`，从 `position - 3s` 起播。理由：字幕/对白常常在暂停点前一句。
2. **快进步长可配（默认 10 秒）+ 长按加速倍率可配（默认 2x）**：`Keymap.seek_step_ms` 已经参数化，UI 只需暴露两个下拉。
3. **默认音轨 / 默认字幕语言**：一次设定，之后每集自动选；匹配不到时**不静默**，在控制栏提示「本集无简体中文字幕」。
4. **连播三件套**：预加载下一集（提前 10 秒打开下一集的首帧）、自动连播开关、下一集倒计时可取消。
5. **定时关闭**：15/30/60/播完本集四种；到点淡出暂停，不直接黑屏。
6. **跳过片头/片尾（时间式）**：每剧记住「片头结束点」「片尾开始点」，只对同剧集生效；可一键撤销本次跳过。

### 3.2 要增强的（我们已有，但比竞品弱）

1. **手势**：双击左右跳转目前是固定值 → 跟随 `seek_step_ms`；长按加速要有**松手回弹**与屏幕角标，避免用户以为卡了。
2. **多版本合并**：同一影片的 4K/HDR/1080p 合成一个条目，播放时按「屏能力 + 带宽 + 上次选择」挑版本，选择结果记忆 7 天。
3. **缓存可见**：设置页拆成「海报缓存 / 元数据缓存 / 转码临时文件」三项，各给数字与清空按钮；清理前说明会失去什么（海报需重下）。
4. **语言偏好与元数据语言联动**：详情页标题/简介语言与「默认字幕语言」分开存，别让改字幕语言顺手改掉片名语言。
5. **播放记录**：独立「记录」页（近 7 天、按类型筛选、文件名搜索），同时是「继续观看」的数据源。

### 3.3 评估后做（有差异化价值，但要先解决成本）

1. **AI 字幕（本机识别）**：竞品把它当 PRO 卖点，说明需求真实。我们的优势是已有模型配置与 AI 陪看管线；风险是移动端算力与包体。做法：桌面（macOS/Windows）先上本机 Whisper 系模型，移动端只做「云端识别 + 明确提示上传音频」；模型管理复用现有页面，**不新开一套设置**。
2. **弹幕**：中文长视频场景的刚需，但涉及源合规与渲染性能。做法：只做「外部弹幕 API 接入」（用户自填地址，三个槽位足够），默认关闭；Rust 线放到 M4 之后，不阻塞 M3。
3. **App 锁 / 家长控制**：轻量版即可——四位密码锁片库入口 + 分级上限（沿用元数据里的分级字段）。不做 Face ID（跨平台成本高），留系统生物识别以后接。

### 3.4 不做

| 项 | 理由 |
| --- | --- |
| PRO 订阅墙 | SeeWow 是开源免费产品，把「倍速/刮削/语言偏好」锁起来会直接违背定位 |
| 多网盘账号矩阵（12 家） | 维护成本高于收益；`openlist`/WebDAV 一条通路覆盖大多数网盘 |
| iTunes 资料库同步 | 苹果生态专属，与跨平台主线冲突 |
| HDMI 5.1 直通（移动端） | 手机/平板极少有 HDMI 多声道链路；桌面端在 M5 音频链路里按需做 |
| Google Cast | 先看 Chromecast 用户占比，M6 后再评估；AirPlay 已有 PiP 通路 |
| 「实时预览」拖动缩略图 | 成本高（需要独立解码缩略图流），M6 性能阶段再评估 |

## 4. 落点

| 工作 | 里程碑 | 备注 |
| --- | --- | --- |
| 续播回退、步长/倍率偏好、默认语言、连播、定时关闭、跳过片头片尾 | Rust M3（T-10 ~ T-15） | 纯策略先进 `core`，UI 后接 |
| 多版本合并、语言联动、缓存分项 | Flutter 1.18 + Rust M4 | 两条线共享规则，先改 Flutter 验证 |
| AI 字幕（桌面本机 / 移动云端） | Flutter 1.19 评估 → Rust M5 | 复用 AI 陪看的模型管理 |
| 弹幕外部源 | Rust M4 之后 | 默认关闭，三个 API 槽位 |
| App 锁 / 分级 | Flutter 1.18 | 轻量四位密码 |
| 记录页 | Flutter 1.18 | 与「继续观看」同源 |

## 5. 对 Rust M3 的直接影响

1. `crates/core/src/resume.rs`：增加 `rewind_ms`（默认 3000），`ResumePoint::Continue` 返回 `position - rewind_ms`（不小于 0）。
2. `crates/core/src/keymap.rs`：`Keymap` 已有 `seek_step_ms` / `volume_step`；补 `hold_speed: f64 = 2.0`（长按加速倍率，供手势层读）。
3. 新增 `crates/core/src/preferences.rs`（T-15）：默认音轨/字幕语言、默认倍速、连播、定时关闭、片头片尾标记的**纯数据 + 校验**，落盘交给 library。
4. 跳过片头片尾需要「按剧集记时间点」：`crates/library` 增一张 `chapter_marks` 表（剧 ID + kind: intro_end / outro_start + ms），M3 只做单机 SQLite。

## 6. 未被截图覆盖但值得记一笔的

- 两家都没把「播放失败」做成设置项，但都有一句「转码=原画质/自动」——**失败时的降级路径**比设置数量重要。SeeWow 应在 M3 就把「解码失败 → 提示 → 换软解重试」写成明确路径。
- Infuse 的「发送匿名错误报告」是默认开启的；我们应当**默认关闭**并在首次崩溃后询问，这与开源产品的信任模型一致。
