## 0. 为什么有这份文件

M1 的 PRD、HLD、任务表、ADR 原本放在 `/tmp/dsh-crew/...`，那个目录随任务结束被清掉，仓库里没有副本。结果是：M1 的代码还在、发布包还在，但**为什么这么写、下一步做什么、什么算做完**全部只剩代码注释里的片段引用。

这条线还要走 M2 到 M6，横跨很长时间。为了不跑偏，规划必须放在 git 里、跟着代码走。本文件是重建版：M1 的事实从代码、发布记录和 `state.json` 反推，M2 起是本轮重新写的、可执行的计划。

## 1. 定位与边界

- **它是什么**：Flutter 主线的下一代内核。Rust + Slint 做界面，libmpv 自持窗口播视频，macOS 首发（Apple Silicon / Intel），GPL-3.0。
- **它不是什么**：不替换 Flutter 主线的发布节奏（1.17、1.18 照常发）；不是跨平台一次做完；不在 M2 碰网络片源、HDR、设计系统。
- **两条线的关系**：Flutter 线是行为基准。Rust 线的解析、去重、进度、收藏规则要和它对齐，差异必须登记（见第 6 节 D-04）。

### M1 已交付的事实（作为基线，不改动）

- `crates/player`：`host`（mpv 事件循环与快照）、`window`（按类名 `swift.Window` 定位宿主窗口）、`probe`（HDR 判定，`video-target-params` 口径，`max-luma` 单位 cd/m²）。
- `crates/ui`：`overlay`、`hit`（输入路由）、`skeleton`（Slint 壳）。
- `crates/app`：composition root，0.1s tick 维护叠层/全屏/换屏；`SEEWOW_SELFTEST=1` 走脚本化自检。
- `crates/core`、`crates/library`、`crates/sources`：**只有 crate 登记，没有实现**——这是有意的，M2 起填。
- 打包：`scripts/make-app-m1.sh` 出 ad-hoc 签名的 `SeeWow.app`，libmpv 改 @rpath；自包含打包属 M6。
- 已知欠账（不阻塞 M2）：M1 验收未跑；`host.rs` 里的临时 mpv 调用要等 M3 的 `mpv.rs` 收编；没有 CI 构建 Rust（目前只有 Flutter 的 `flutter.yml`）。

### 2.1 M3–M6 验收草案（每个里程碑开工时再细化，门槛只增不减）

**M3 · 本地播放手感对齐 Flutter 1.0**

- 播放/暂停、音量、±10 秒、倍速、全屏、键盘快捷键与 Flutter 版逐项对照可用。
- 断点续播：关掉重开回到上次位置；进度写库幂等。
- 字幕：内嵌文字轨可切换，外挂 SRT / VTT 可加载；编码错误有提示不崩。
- 1080p30 本机播放连续 30 分钟丢帧 ≤ 2 帧（mpv 统计口径），内存稳定不增长。
- 关窗退出不留孤儿进程，日志无 panic。

**M4 · SMB / WebDAV / IPTV**

- WebDAV：Basic 认证列目录、Range 播放、认证失败可读提示。
- SMB：macOS 经 NetFS 挂载后扫描与播放（不自己实现 SMB 协议栈）。
- IPTV：M3U / TXT / JSON 列表导入，XMLTV 节目单解析，频道可播。
- 网络中断、401、超时都不崩溃；旧片库保留。

**M5 · HDR10 端到端 + Dolby Vision**

- HDR10：pq / bt2020 / 10bit / EDR 管线证据齐全，真 HDR 屏上`probe_verdict`判为「已上屏」。
- SDR 屏：判为「管线已通、未上屏」，画面正确降级（不灰不爆）。
- DV P5/P8：至少能识别 profile 并选择正确分支；若本轮不做完整 DV 渲染，必须在发布说明里写明边界。

**M6 · Cinema Editorial + 性能 + 发布**

- 设计令牌落到首页、详情、播放三个主界面；浅色/深色都可用。
- 1 万条片库冷启动 < 1 秒；4K 播放内存 < 300 MB。
- 自包含打包：libmpv 与依赖全部进包，换一台没装 Homebrew 的 Mac 能直接打开。
- 签名与公证可用；发布清单含安装包 SHA256 与回滚说明。

## 3. M2 计划（本轮）

**目标一句话**：给一个本地目录，能扫出片库、解析出片名/年份/季集、存进 SQLite、重启不丢，并且收藏、进度、搜索、筛选都能查对。

**明确不做**：不做播放器改动、不做网络片源、不做 HDR、不做最终视觉设计、不接 AI。

### 3.2 每项 DoD（别人照着做能得出是/否）

- **T-02**：`cargo test -p seewow-core` 绿；错误枚举覆盖 IO/解析/配置/数据库四类且 `Display` 有可读中文；路径在测试里可用 `SEEWOW_DATA_DIR` 覆盖，不写死用户主目录；配置默认值明确、坏配置返回错误而不是 panic。

| `serde` + `serde_json` | 配置、`--json` 输出 | `serde_json` 已随 Slint 存在于构建图，转成直接依赖几乎零成本；手写 JSON 解析是纯风险 | 已登记（D-01） |

## 5. 防跑偏规则（长期有效）

1. **一个任务只改它登记的文件。** 顺手重构、顺手美化一律回退；确实需要动别的文件，先改本文件的任务表。
2. **先红后绿。** 每个任务先写会失败的测试，提交信息里写真实数字（通过/跳过/失败），不写「应该没问题」。
3. **三条命令是硬门槛**：`cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`。任一条不过，任务不算完成。
4. **行为差异必须登记。** 与 Flutter 主线不一致的地方写进第 6 节，并配一条测试固定它；不登记的差异视为缺陷。
5. **里程碑只增不减。** 要删一条 DoD 或降一个门槛，需要你（项目所有者）明确同意，并记录日期与理由。
6. **每个里程碑结束写「回看」**：完成什么、没完成什么、为什么、下一个里程碑是否要调整。写在本文档末尾，不写在聊天里。
7. **文档跟着代码走。** 规划、决策、验收记录只存在于 git；不放 `/tmp`、不放任务临时目录。
8. **M1 验收冻结不等于不用管。** M2–M6 任何改动导致 M1 的探针/窗口行为回归，按阻塞缺陷处理。
