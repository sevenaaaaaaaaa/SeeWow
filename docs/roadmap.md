# SeeWow 路线图（2026-11-17 起）

> **单一事实源**：版本号、平台、优先级、发布门禁以本文为准。发布说明只回答"这一版改了什么"，不再承担路线职责。
> 关联文档：[质检与复盘](audit/2026-11-17-quality-audit.md) · [版本汇总](release-index.md) · [Rust 内核线计划](plan/rust-rewrite-plan.md) · [跨端对齐](parity.md)
> 维护规则：每个里程碑结束时在本文件末尾追加一段「回看」，只增不删。

## 0. 判断：问题不在"发得不够快"

从 1.0.0 到 1.18.0（11 天，17 个版本），用户感知到的改善却集中在少数几版；资源管理（本地目录、Plex）从 1.7 就在报，到 1.18 一行没动。原因已在 [质检报告](audit/2026-11-17-quality-audit.md) 拆开：

- 缺陷没有登记入口（0 issue），所以"上次说的那条"不会进入下一版的范围；
- CI 只编译不测试，所以回归没人拦；
- 两条产品线（Flutter 五端 / Rust macOS）共用一份注意力，但没有共同的交付出口。

**路线图的第一原则因此不是"加功能"，而是"让每一条修复可被登记、被验证、被发布"。**

---

## 1. 两条线，两个出口

| 线 | 代码 | 服务对象 | 发布物 | 节奏 | 谁能受益 |
| --- | --- | --- | --- | --- | --- |
| **A · 产品主线** | `apps/seewow`（Flutter） | 现有全部用户 | 1.x 预览包（五端） | 按里程碑，2–3 周一个 | macOS / iOS / Android / Windows / Linux |
| **B · 内核线** | `apps/seewow-rs`（Rust + mpv + Slint） | 未来的 macOS 桌面 | 2.0 预览包（仅 macOS） | 按 M1–M6，不按周 | 只有 macOS |

**三条硬规则**

1. **A 线只修不扩**，直到资源管理与对齐清零。新功能要进 A 线，必须先回答"它修了哪个已登记缺陷"，否则排到 P3 之后。
2. **B 线不发用户可见版本**，直到 M5（HDR 端到端）通过；GitHub 上只保留 `v2.0.0-mN` 验收包，不写"新版本"。
3. **不承诺移动端由 Rust 受益**（决策 D-12）。任何"移动端也能用"的说法，必须落回 A 线。

## 2. 版本与发布纪律

**版本号**：`MAJOR.MINOR.PATCH`
- `PATCH` 只修缺陷（1.19.1、1.19.2…），不含新功能；
- `MINOR` 加功能或完成一个里程碑；
- 预发布统一后缀 `-preview`（仅用于内部验收包，不建 GitHub Release）。

**一次发布必须同时满足（缺一条就不发）**

| 项 | 要求 |
| --- | --- |
| 平台 | 五端资产齐全，或在发布说明顶部用一张表逐项写明"本版未出包，当前可用版本是 X" |
| 校验 | `SHA256SUMS.txt` 作为资产上传，不只写在正文 |
| 变更记录 | `CHANGELOG.md` 一行 + 详细说明链接；每行引用 issue 编号 |
| README | 下载表与本版资产逐行一致（含"仍是旧版"的三行） |
| Latest | GitHub Latest 指向当前最新可用预览版；更早版本保持 Pre-release |
| 缺陷 | 发布说明新增固定小节「本版未修」，列出已知未修缺陷编号 |

**分支与提交**：`main` 直推改为 `crew/<主题>` 分支 + PR（哪怕自己合并）。理由：PR 是唯一能让 CI 在合并前拦一次的地方。

## 3. 阶段计划

### P0 · 止血：1.19.0「资源管理修复版」（本周）

**目标**：让"加来源 → 管理来源 → 断开"这条链不再丢数据、不再卡、不再骗人。
**范围**：只做下面 8 条，不加任何新功能、不碰 Rust 线。

| 编号 | 事项 | 验收（别人照着能做） |
| --- | --- | --- |
| RM-01 | 断开来源二次确认 + 文案写清会移除多少条目 | 点"断开"先弹确认；取消后条目与进度不变；确认后条目消失且不可恢复提示明确 |
| RM-02 | 父子目录重叠拦截（或全局按 id 去重） | 先加 `/Movies` 再加 `/Movies/2024`，片库不出现重复卡片；进度写入两条一致或只有一条 |
| RM-03 | 来源可停用 | 停用后"刷新片库"不再请求该来源；条目、收藏、进度保留；重新启用可恢复扫描 |
| RM-04 | Plex 改资料库选择不重登录、不强制重扫 | 编辑弹窗内直接改选；保存后只重扫受影响范围；不出现验证码流程 |
| RM-05 | Plex 重复 ratingKey 跳过而非整库失败 | 构造重复条目，扫描完成并提示"跳过 N 条"，旧条目不被清空 |
| RM-06 | 播放进度与片库写入分离（节流） | 1 万条片库播放 10 分钟，落盘次数 ≤ 40 次；退出应用后进度不丢 |
| RM-07 | 来源条目数缓存 | 10 来源 × 1 万条目时来源页滚动不掉帧（DevTools 帧时间 < 16ms） |
| Q-01 | CI 增加 `flutter test` + `flutter analyze` | PR 上跑通；故意改坏一条断言 → CI 红 |
| Q-02 | Latest 指向 1.19.0，五端资产 + SHA256SUMS | Releases 页默认下载为 1.19.0；五个资产与校验文件齐全 |

**本轮新增测试（必须先进测试再修）**：重叠目录、断开确认、Plex 改选、重复 ratingKey、进度节流上限。

**DoD**：`flutter analyze lib test` 0 error / 0 warning；`flutter test` 全绿且较 1.18 基线净增 ≥ 8 项；CI 两条新门槛生效；iOS + Android 各一台真机跑完"加本地目录 → 重扫 → 播放 → 断开"并留记录。

### P1 · 对齐：1.20.0「两端一致」

**目标**：把"一套代码五端"的承诺变成可核对的表。

- 刷新 `docs/parity.md`：逐条按代码复核，标注"共享 / 桌面独有 / 移动独有 / 无法对齐"，每条附文件路径；
- 移动端入口复查：来源管理、下载、播放设置三项在 375px 下可完整操作；
- 桌面三平台包恢复同时发布（Windows / Linux 断档 12 版）；
- 真机矩阵入档：iOS 17、Android 13 各一台，记录版本、构建号、四步链路结果。

**DoD**：parity 表每行都能指向代码或真机记录；五端资产同版；README 下载表无需"仍是旧版"备注。

---

### P2 · 稳定与性能：1.21.0「大库不卡」

**目标**：1 万条片库可用。

- 增量扫描：按 mtime + size 跳过未变文件，避免每次全量 stat；
- `library.json` 迁到 SQLite（schema 可直接借 B 线 `crates/library`，两边字段对齐）；
- 冷启动、首屏、扫描耗时三个数字入档，作为后续版本不得退化的基线；
- 崩溃与错误上报：本地日志 + 一键导出（不联网）。

**DoD**：1 万条片库冷启动 < 2 秒、全量扫描 < 90 秒、增量扫描 < 5 秒（同一目录无改动）；三个数字写进发布说明。

---

### P3 · 内核：2.0.0（仅 macOS）

按 [Rust 内核计划](plan/rust-rewrite-plan.md) 推进，顺序不变：M3 播放手感 → M4 网络片源 → M5 HDR 端到端 → M6 设计与打包。

**新增两条约束**（写进该计划的里程碑表）：

1. M4 结束前，B 线必须自己完成一次"加本地目录 → 扫描 → 播放 → 断开"的闭环，行为以 A 线 1.19 为基准，差异逐条登记；
2. 任一 A 线修复若同样存在于 B 线，必须在同一里程碑内跟进，否则在计划里登记为已知差异。

**DoD**：M6 通过后，2.0.0 能替换 1.x 的 macOS 包，且 A 线的资源管理缺陷不复发。

## 4. 门禁（每个 PR / 每次发布都跑）

| 层级 | 命令 / 动作 | 不过怎么办 |
| --- | --- | --- |
| 代码 | `flutter analyze lib test`（0 error / 0 warning） | 阻塞合并 |
| 单测 | `flutter test --concurrency=1`（全绿，净增不为负） | 阻塞合并 |
| 内核 | `cargo fmt --check` / `clippy -D warnings` / `cargo test` | 阻塞合并（已在 CI） |
| 真机 | P0/P1 里程碑结束时 iOS + Android 各一台，四步链路 | 里程碑不结项 |
| 发布 | §2 六项清单逐项打勾 | 不发版 |

---

## 5. 明确不做 / 暂缓

| 事项 | 决定 | 理由 |
| --- | --- | --- |
| 新功能入口（专题、皮肤、Agent、AI 陪看） | 暂缓到 P0/P1 完成 | 当前每加一个入口都在放大资源管理的维护面 |
| 桌面系统级画中画 | 保持现状（置顶小窗 + 移动系统 PiP） | 需独立悬浮窗口工程，投入产出比低 |
| 豆瓣在线刮削 | 不做 | 无公开 API |
| Rust 内核移植到 iOS | 不做（D-12） | 依赖全是桌面栈，成本远超收益 |
| 商店签名与公证 | 暂缓 | 先解决"装到的是哪一版"，再解决"怎么装" |

## 6. 风险与触发信号

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |
| P0 又被新功能挤掉 | 1.19.0 范围里出现"顺便加个…" | 新需求一律进 backlog，不进本版 |
| 两条线再次抢注意力 | B 线改动开始出现在 1.x 发布说明 | 发布说明按线分节，禁止混写 |
| 修复没有回归网 | 同一缺陷第二次出现 | 该缺陷必须有测试，否则不发版 |
| 真机验证继续缺席 | 里程碑结束时没有设备记录 | 里程碑不结项，写进回看 |
| 文档再次分叉 | 出现第二份"计划"或第二份"对齐表" | 只允许 `docs/roadmap.md` + `plan/rust-rewrite-plan.md` 两份规划，其余归档 |
