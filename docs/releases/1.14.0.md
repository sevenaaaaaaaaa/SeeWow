# SeeWow 1.14.0 · 跨端对齐检查

这一版没有加新功能，专门检查移动端与电脑端是否对齐，并修掉检查中发现的几个入口差异。完整矩阵见 [docs/parity.md](../parity.md)。

## 结论

- 产品功能本身来自同一套 Flutter 代码：首页、片库、详情、片单、Agent、直播、音乐、解耦空间、播放器、离线缓存、转码清晰度、限速与剩余时间，双端一致。
- 差异集中在系统能力：SMB、遥控主机、迷你窗、目录选择是桌面独有；媒体权限、SAF、系统 PiP、本地网络权限是移动独有。
- 手机只做遥控客户端、桌面做主机，是当前设计，不是遗漏。

## 本轮修复

- 移动端离线缓存页移除「选择存放位置 / 打开文件夹」：这两个操作在手机上要么没有系统目录选择器，要么打开后无反应；现在改为说明「缓存保存在应用文档目录，可在系统文件中查看」。Android 不再调用不支持的目录选择器。
- 移动端底部「更多」从直接跳设置改为面板：可直接进入「我的片单 / 直播 / 音乐库 / 设置」，与桌面侧栏入口对齐，当前所在分区的选中状态也不再误导。
- 窄屏顶栏的「主空间 / 解耦空间」从文字标签改为图标按钮，避免和搜索、刷新、收藏挤在一起；解耦空间横幅在手机上改为 16px 边距。
- 新增 [跨端对齐说明](../parity.md)，把共享能力、桌面独有、移动独有与无法对齐的差异写清楚。

## 仍然存在的差异

- **移动端 SMB**：系统没有公开 SMB 客户端 API，继续使用 WebDAV / OpenList / File Station。
- **iOS 画中画**：AVKit 不接受自定义认证头，Plex / Emby 带令牌的网络流无法直接 PiP；先缓存到本机后可以画中画。桌面迷你窗不受影响。
- **移动后台下载**：锁屏后系统可能暂停任务，重新打开 App 继续；桌面可一直下载。
- **手机作为被控端**：当前不开放，后续如有需要再加。
