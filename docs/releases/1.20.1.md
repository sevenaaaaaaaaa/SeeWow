# SeeWow 1.20.1 · 离线缓存修复版

这一版只修一件事：**已经下载到本机的文件，必须能在离线时被找到并播放**。

## 为什么会有这一版

1.20.0 之后收到两条真机反馈：

1. 「本地已经缓存了，但在媒体库选『已缓存』时看不到 Plex 的缓存；文件夹里明明有文件」；
2. 「在离线缓存列表里点播放，已经缓存的文件也要联网验证，否则就认为播不了」。

同一处根因的两种表现。

## 根因

- **缓存判定依赖任务 id 与状态**：`hasOffline` / `pathFor` 只按 `task.itemId` 查找，并且要求 `status == completed`。Plex 来源重新连接后，库里的条目 id 会变（`sourceId:ratingKey`），旧任务 id 对不上，文件在磁盘上也被判为“没缓存”。另外 `taskFor` 只取第一条任务：一次失败重试后，第一条仍是 failed，`pathFor` 返回 null。
- **离线播放绕回片源**：`_playDownload` 先按 id 找库条目，再走 `_play` → `prepare()`；`prepare()` 把 locator 换回 Plex 的远程地址，于是播放器直连服务端，断网/服务离线就失败。下载页的“离线播放”实际上从来没打开过本地文件。

## 修了什么

- **匹配按文件与标题，不信状态**：新增 `playableTasks`（只看 `filePath` 是否真的存在），先按 id 精确匹配，再按「同来源 + 同标题」匹配；来源重连导致 id 变化时，标题唯一也能认出来。标题归一化保留中文等非拉丁文字（去掉空白与标点、拉丁转小写）。
- **多任务取真正有文件的那条**：`pathFor` 从后往前找存在文件的任务，失败重试留下的旧任务不再挡住播放。
- **媒体库「已缓存」用新的匹配集合**：`cachedItemIds` 一次遍历任务、每任务只做一次文件检查；筛选与计数都走它，Plex 重连后的条目也能出现在「已缓存」里。
- **离线播放直给本地文件**：下载页点「离线播放」直接把 `file://` 地址交给播放器；解析器遇到 `file:` 直接返回，不再走片源 `prepare()`。即使条目已从片库移除，也能用缓存任务里的标题与来源构造条目播放。
- **文件丢了就说清楚**：状态为完成但文件被移动/删除时，下载页显示「文件已丢失」，隐藏播放按钮，并明确「不会自动回落到联网播放」，只留删除记录与重新缓存。
- **全局入口**：顶栏新增「离线缓存」图标（有进行中的下载时显示数字角标），任意页面一键进入缓存管理；设置页的入口保留。
- **附带修复**：下载页与缓存弹窗的存放位置 Future 之前写在 `build` 里，会在每次完成时重建并反复触发，测试中会空转；改为在 State 里只解析一次。

- `flutter test` → 373 通过 / 2 跳过 / 0 失败（新增 9 条：缓存匹配与状态容错 5、下载页缺失/可播 2、媒体库重连筛选 1、顶栏入口 1）；

- 新增 `test/offline_cache_test.dart`、`test/downloads_page_test.dart`，扩充 `test/library_offline_filter_test.dart` 与 `test/experience_test.dart`。

## 数据与升级

- 存储结构不变；`downloads.json` 继续按原格式读取。
- 旧任务不需要重新下载：匹配会按标题找回；只有文件真的不在磁盘上时才显示「文件已丢失」。
- 版本号 1.20.1+24；三端已重新构建。
