# SeeWow 1.7.1 · 修复预览版

这一版修 1.7.0 里暴露出来的三处接入问题：本地目录扫描、飞牛 / NAS 的 SMB 凭据与挂载、Plex 登录方式。没有新增内容型功能。

## 本地文件夹

- 选择磁盘根目录等特殊路径时不再因为取不到文件夹名而报错。
- 扫描改为逐目录容错：某个子目录没有访问权限、外接盘掉线或个别文件读不到时，跳过该项并继续扫描其余媒体，不再整库失败。
- 添加失败时提示具体原因（例如权限、路径不存在、连接重复），不再只显示笼统的「未能打开文件夹」。
- 目录选择框仍走系统面板；如果 macOS 拒绝访问所选位置，请在「系统设置 → 隐私与安全性 → 文件与文件夹」中允许 SeeWow。

## 飞牛 / NAS（SMB）

- 地址可直接填 `192.168.1.10/共享名`、`\\192.168.1.10\共享名` 或完整的 `smb://`，保存前自动规范化；账号和密码仍填在单独字段。
- 凭据恢复增加文件兜底：macOS 每次临时签名发版都会让钥匙串认为凭据来自「另一个应用」，升级后可能弹密码框或读不到旧项。现在钥匙串不可用时回退到 Application Support 内 0600 权限的 `secrets.json`，飞牛、群晖、WebDAV、Plex 的凭据不会静默丢失。
- SMB 挂载移到后台线程，连接慢或失败时界面不再卡住；错误区分为认证失败、挂载失败和系统不支持。
- 未填写账号密码时按访客 / 当前用户挂载，而不是提交一个空密码。

## Plex

- 新增「使用 Plex 账号登录」：应用向 plex.tv 申请 4 位验证码并自动打开 https://plex.tv/link，登录完成后自动列出账号下的服务器。
- 多个服务器时让你选择；连接优先局域网直连，其次 HTTPS，再退到中继。选定后自动填入服务器地址和 Token，直接开始扫描与导入。
- 保留原来的「服务器地址 + Token」手动连接方式，方便已有 Token 或无法打开浏览器的场景。

## 验证范围

- 210 项自动化测试通过、2 项原生解码器测试按需跳过；静态分析 0 error、0 warning。
- 新增覆盖：SMB 地址规范化、无权限子目录不中断扫描、Plex PIN / 服务器选择 / 连接排序（本地模拟 plex.tv HTTP 服务）。
- 已对真实 plex.tv PIN API 发起请求，能创建 4 位验证码；**没有用真实 Plex 账号完成登录 → 服务器列表 → 扫描全链路**，需要你实测确认。
- 本地目录添加用 /tmp 与常用目录实测通过；飞牛 SMB 未连接到真实设备验证，错误提示与凭据兜底需要实际升级路径验证。
- macOS 若仍弹出「SeeWow 想要使用钥匙串中的机密信息」，是系统对旧签名的正常询问：允许会用钥匙串；拒绝也会回退到文件凭据，功能不受影响。
