# SeeWow 1.19.0 · 资源管理修复版

这一版**不加新入口**，只修一件事：来源加进来之后，能管、能停、能断，断了不丢东西。

## 为什么先修这里

- 12 天发了 17 个版本，资源管理（本地目录 / Plex）从 1.7 报到 1.18 一行没动；
- 根因不是没修，是**缺陷没有入口**（仓库 0 个 issue）、**CI 只编译不测试**；
- 所以这一版同时补上这两件事：九条缺陷有了编号（#2–#10），CI 有了阻塞门禁（#11）。

## 修了什么（按你摸得到的顺序）

| 编号 | 现象 | 现在 |
| --- | --- | --- |
| RM-01 | 点「断开来源」立刻执行，收藏与续播点一起没了 | 先弹确认，写明「将移除 N 个条目，连同收藏与续播进度」 |
| RM-02 | 先加 `/Movies` 再加 `/Movies/2024`，同一部片出现两次、进度分裂 | 添加时拒绝重叠目录，并告诉你被哪个来源覆盖 |
| RM-03 | 离线的 NAS 拖住每次刷新，只能删掉来源 | 来源可停用；停用后不参与刷新与刮削，条目与进度保留 |
| RM-04 | Plex 想少导入两个资料库，要重新走验证码 + 全库重扫 | 编辑弹窗「重新选择资料库」，复用已存 token，不重登录 |
| RM-05 | Plex 返回重复条目，整库扫描失败 | 跳过重复并计数，扫描继续 |
| RM-06 | 播放时每 5 秒重写整份片库 JSON | 进度单独写 `progress.json`，20 秒节流，关播放器补写 |
| RM-07 | 来源页每行都遍历全库计数 | 按 revision 缓存，一次算完 |
| RM-08 | 重扫手工重建来源，1.16 就因此丢过 `folders` | 改用 `copyWith`，只更新 `lastScan` |
| RM-09 | 文件名含 `sample` 的正片被静默跳过 | 改为词元匹配，`The Sampler` 正常入库 |

## 工程

- **CI 门禁**：`.github/workflows/flutter.yml` 的 macOS job 增加 `flutter analyze`（error / warning 阻塞）与 `flutter test --concurrency=1`，跑在构建之前；
- **第一次真实运行就抓到债**：两条 XMLTV 测试依赖本地时区（一条断言 `start.hour == 12`，一条用本地时钟配 `+0800` 造数据），UTC runner 上必红。已改成按 instants 断言，`TZ=UTC` 与 `TZ=Asia/Shanghai` 双绿；
- **测试**：307 → **321 通过 / 2 跳过 / 0 失败**（新增 14 条：资源管理 7、来源操作 2、sample 1、plex 重复 1、plex 改选 1、进度落盘 2）；
- **静态检查**：`flutter analyze lib test` → 0 error / 0 warning（426 条历史 info，与改动前同源）；
- **CI 提速**：缓存 Homebrew 下载目录并关闭自动更新，避免每次重装 mpv。

## 数据与升级

- `library.json` 结构未变，直接从 1.18 覆盖安装即可；
- 新增 `progress.json`：只存播放位置、时长与最近播放时间；旧版本不认识它，会忽略；
- 从 1.19 降级到 1.18 会丢最后 ≤20 秒的进度，其余数据不受影响；
- 断开来源仍然只删本机记录，不动磁盘上的文件。

## 本版未修（写在明面上）

- **RM-05 的跳过数量还没显示到界面**：扫描器已计数（`PlexScanner.lastSkipped`），提示文案留到下一版；
- 桌面系统级画中画（macOS 悬浮窗）仍未做；
- 下载内核重做、HLS / 直播离线缓存仍未做；
- Bangumi 真实服务仍只有协议级测试（构建机到 api.bgm.tv 超时）；
- 移动端真机矩阵（iOS / Android 各一台）仍待补：本地目录权限、Plex 改选、后台下载。

## 与前几版的关系

- 1.18.0：只修构建身份（版本号不再写死 1.6.0）；
- 1.17.0：多源元数据与自动解说；
- 1.19.0 不动元数据、不动播放器行为，只动资源管理与持久化。
