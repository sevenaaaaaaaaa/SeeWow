# 能力深度挖掘与交互重构 · 产品规划

> 日期：2026-11-23 · 基线：1.21.4 (30) 本地包 · 依据：仓库实测、真网探针、494 条测试
> 结论先行：**问题不是能力少，是能力停在同一层——每家都在"能打开"，没有一家在"替你决定"。**

---

## 0. 三句话诊断

1. **能力是按数据源长的，不是按用户目标长的。** 本地库、在线采集站、直播、短剧、音乐各有一套页面：10 个分区、22 个弹层文件、38 处 `showDialog`/`showModalBottomSheet`、`sources_view.dart` 单文件 2035 行。用户想的是"今晚看什么、能不能看"，界面回答的是"你从哪个数据源来"。
2. **聚合停在请求层，没到作品层。** `OnlineSearchHit` 是一个 `(站点, 条目)` 一行，只按片名排序：同一部《流浪地球》在 5 个采集站就是 5 行结果，用户要自己比对哪条能播。真正的聚合应该是**一部作品一行**，后面挂着"哪几个源有、哪个最清晰、哪个能直连"。
3. **差异化能力都在，但都只做了 60%。** 豆瓣免费元数据 + 评论、批量刮削、20 个实测可播采集站、Agent 选片、手机遥控、离线下载——每一项单独看都能打，但没有一项做到"别人抄不走"，因为它们彼此不通：刮削出来的封面不会自动参与推荐，评论不会解释推荐，遥控端不知道你在电脑上刮了什么。

## 1. 现状审计（诚实打分）

评级口径：**有**＝能用但不构成理由；**强**＝同类里不弱；**独家**＝别人没有或做不动的组合。

| 能力 | 现状 | 评级 | 差在哪 |
| --- | --- | --- | --- |
| 本地片库扫描 | 文件名解析、NFO、多目录 | 强 | 与在线源完全隔离 |
| 在线采集站 | 20 个实测可播站，CMS 直连 | 强 | 只做"请求并发"，没做"作品聚合" |
| 免费元数据 | 豆瓣 + AniList，封面/评分/评论 | 强 | 只接进手动匹配与批量刮削，未进入发现与推荐 |
| 批量刮削 | 只补空白、不碰已确认、限流退避 | 强 | 不自动跑；无覆盖率视图 |
| 播放内核 | libmpv/media_kit，HDR 探针 | 强 | 无"这个源能不能直接播"的前置判断 |
| 直播 IPTV | TVBox 配置导入 | 有 | 与点播两张皮 |
| 短剧 | 采集站短剧分类浏览 | 有 | 只在"在线源"里，首页无入口 |
| Agent 选片 | 自填模型 API | 有 | 无法解释"为什么推荐这部"，也不看你的评论数据 |
| 手机遥控 | 局域网桥接 | 强 | 一次性连接，不共享片库状态 |
| 离线下载 | 队列、断点、缓存匹配 | 强 | 不与"多源择优"联动 |
| AI 字幕/配音/解说 | 通用 JSON 适配 | 有 | 三条各自独立，无统一任务面板 |
| 皮肤/标识 | 液态玻璃 + 皮肤工作室 | 有 | 视觉是加分项，不是护城河 |

**一句话**：强项集中在"能不能播"，弱项集中在"替我做决定"。而用户付钱/留存的理由从来是后者。

---

## 2. 三个结构性原因

### 2.1 入口按数据源分，不按意图分
底部 4 个固定席 + 第 5 席"更多"，二级再分在线源/直播/短剧/片单/音乐/设置。任何一个意图（"看《庆余年》"）都要先选数据源：本地？在线？直播？——而用户根本不知道自己的片在哪。

### 2.2 聚合粒度错了一级
- 现在是"站点 × 条目"：5 个站 = 5 行。
- 应该是"作品 × 可播性"：1 行，写着 `豆瓣 8.3 · 5 个源 · 最优 1080p 直连 · 已缓存 2 集`。

差这一级，产品就从"能搜到"停在"能搜到"，永远走不到"替你选好"。

### 2.3 差异化能力之间没有总线
刮削、评论、推荐、下载、遥控各写各的。缺一条"作品对象（Work）"作为公共主语：一旦有了它，封面、评分、评论、源、进度、下载、遥控就都挂同一个 ID 上。

## 3. 定位重述与取舍

**定位（一句话）**：给中文用户的一台"私人影院调度台"——把你自己的片库和全网可直连的片源编成同一张节目单，替你判断今晚看什么、从哪个源看。

**三条不做**（砍掉才有强度）：
1. 不做在线影视站（不承载版权内容，只做直连与索引）。
2. 不做通用下载器 / BT 客户端（只做"这部片现在能不能落盘"）。
3. 不做社交与片单广场（评论只作为**证据**引用，不做社区）。

---

## 4. 三个独家能力（按可辩护性排序）

### A. 一块幕布 Source Loom —— 作品级多源编排

**用户场景**：输入"庆余年"，不问它在哪。系统给出**一部作品**：豆瓣评分与 3 条评论摘要；本地库有 12 集已缓存；在线 5 个源有全集，其中 2 个直连 m3u8、1 个 1080p；点一下从最优源第 1 集开始播，第 2 集起后台预取。

**机制**：
1. 搜索扇出（本地索引 + 豆瓣 + 20 采集站 + 直播 EPG），全部落到 `Work` 对象（豆瓣 id 为主键，缺失时用归一化片名+年份生成）。
2. 每条播放地址做**可播性判定**：直链 m3u8/mp4 → 可直连；分享页 → 需要解析（标注"需网页解析"，不假装能播）；有防盗链 → 标注。
3. 打分排序：直连 > 需解析；清晰度；集数完整度；源的历史成功率（本地统计）。
4. 一键起播 + 增量预取；失败自动切下一源（不是弹错误框）。

**为什么别人抄不走**：TVBox 系只有在线、Plex/Jellyfin 只有本地，两边都不做"作品级编排 + 可播性判定"。而判定依赖自由网络与真实成功率统计，是沉淀出来的，不是接口能买到的。

**验收**：`搜索→起播` 的平均点击数 ≤ 2；直连命中率 ≥ 85%（用 20 站实测样本）；一源失败自动切换成功率 ≥ 95%。

### B. 品味轨迹 Taste Trace —— 可解释的选片

**用户场景**：首页不再是"猜你喜欢"的黑箱，而是一条**可追溯**的推荐：`因为你给《漫长的季节》打了 5 星，且看过 3 部东北题材；豆瓣上这类片的高赞评论反复提到"生活流"`，下面给 3 部，每部一行理由，点"不同意"就当场改写模型。

**机制**：
1. 推荐必须携带**证据链**：来自你的行为（评分/完播/跳过时间点）+ 来自公开评论的高频词（已有豆瓣评论管道）。
2. "不同意"是一等公民：一次否决立刻改变同题材权重，并记录理由。
3. 冷启动不装懂：库为空时只说"先导一部"，不生成假推荐。

**为什么别人抄不走**：把**中文评论语料**当作推荐证据，需要免费评论管道（已在）+ 本地可解释模型（Agent 已有）。

**验收**：推荐附理由的比例 100%；"不同意"后同题材权重可见变化；冷启动零假推荐。

### C. 口袋影院 Pocket Screen —— 手机是遥控器，也是第二块屏

**用户场景**：手机扫一下连上 Mac，看到的是**同一个片库、同一份进度**；点"下载到手机"就用 Mac 的宽带把片子下好再传过去；出门路上接着看，进度回传。

**机制**：桥接从"一次性遥控"升级为"共享会话"：Same Work/Episode ID、同一进度、任务队列可下发（下载/刮削/预取）。

**为什么难抄**：需要同时拥有桌面播放内核 + 移动端 + 本地任务队列，三者缺一不可。

**验收**：手机发起下载到可离线播放 ≤ 3 步；进度双向同步误差 ≤ 2 秒；断网可用。

## 5. 交互重构：从"5 席 × 38 弹层"到"一条主线"

### 5.1 新的信息架构

- **底部 3 席**：看 / 找 / 我（其余全部收进 ⌘K 命令面板：直播、短剧、音乐、皮肤、设置、遥控、任务）。
- **全局命令面板（⌘K）**：唯一入口。输入片名/粘贴链接/自然语言（"找部两小时的悬疑"）都在这里；结果就是 Work 行。
- **首页三态**，不再假装有内容：
  - 空库 → 一句"先导一部片" + 两个按钮（扫描本地 / 载入免版权示例）。
  - 有库无进度 → "今日可看"（按可播性排序，标明源与清晰度）。
  - 有进度 → "继续看"置顶，其余按时间线。

### 5.2 详情页信息顺序（先能不能看，再是什么片）

1. 一行决断：`可直连 · 1080p · 5 个源 · 已缓存 12 集` + 主按钮「开始看」。
2. 源矩阵：每源一行（清晰度/集数/直连或需解析/历史成功率），可手动换源。
3. 作品信息 + 评论摘要（引用 3 条高赞，点开看全部）。
4. 相似片（带理由）。

现在这四块是散在 4 个弹层里的；改成一条纵向流。

### 5.3 统一任务中心

刮削、下载、导入、预取共用**一个**进度面板（右下角胶囊，点开是队列）。当前是三个地方各显示各的。

### 5.4 状态诚实

空状态、失败、需解析、限流，全部写清**为什么**和**下一步做什么**，禁止"暂无内容"这种既无信息又无出口的文案（1.21.3 已修过一批，这条要成为规则写进 CLAUDE.md）。

## 6. 路线（每阶段一个用户能感到的变化）

| 阶段 | 主题 | 用户能感到的变化 | 主要工作 |
| --- | --- | --- | --- |
| M1 | Work 对象 + 作品级搜索 | 搜一次，只有一部片，后面挂着所有源 | `Work` 领域模型；搜索扇出合并；可播性判定；结果页一行一作品 |
| M2 | 详情页重构 + 一键起播/切源 | 点一下就开始看，坏了自动换源 | 源矩阵 UI；起播器；失败切换；预取 |
| M3 | 首页三态 + ⌘K 统一入口 + 任务中心 | 打开就知道看什么；所有动作一个入口 | 3 席导航；命令面板；任务队列面板 |
| M4 | 品味轨迹（可解释推荐） | 推荐会说"为什么"，能当场否掉 | 证据链模型；评论高频词；否决改写权重 |
| M5 | 口袋影院 | 手机接管同一片库与进度 | 会话桥接；任务下发；离线包 |

顺序理由：M1/M2 是"能力变成独家"的地基（没有 Work 就没有编排）；M3 是交互收敛；M4/M5 建立留存与跨端锁定。**不要并行开工**，否则又回到"每样 60%"。

---

## 7. 指标

**北极星**：`一次会话里成功起播的作品数 / 打开过详情的作品数`（衡量"决定并看到"，不是"点开过"）。

护栏指标：
- 搜索→起播平均点击数（目标 ≤ 2）
- 直连可播率（目标 ≥ 85%，按 20 站样本周更）
- 刮削覆盖率（有封面条目占比，目标 ≥ 90%）
- 空状态死路数（目标 0；每次发版扫一遍）

---

## 8. 风险与不为

- **平台风险**：采集站与豆瓣接口都不稳定（本周实测：豆瓣突发限流静默返空、9/14 旧站失效）。对策：可播性判定 + 历史成功率 + 一键换源，而不是"多接几个站"。
- **版权边界**：只索引直连地址，不代理、不缓存版权内容；下载只服务用户自己的本地/网盘源。
- **复杂度风险**：三席 + 命令面板会砍掉现有入口，需要一次明确的迁移说明（旧路径保留一个版本）。
- **不为**：不做在线影视站、不做 BT、不做社区。这三件一旦开做，产品会重新变成"什么都有、什么都不强"。
